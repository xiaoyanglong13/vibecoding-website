A fully-worked example

The previous page described what an agent can do in the abstract. This page traces one request from a vague instruction to a finished artifact, step by step, so you can see the loop in motion before you install anything yourself.

The request

A student running a small campus pop-up shop has a folder with a month of sales exports and wants a one-page summary to bring to a meeting with a supplier the next morning. The request given to the agent is deliberately vague — this is close to how people actually phrase requests in practice:

Look at the sales data in this folder and put together a
one-page summary I can send to my supplier before tomorrow
morning. I want them to see the month went well.

Notice what is missing: no file name, no definition of "went well," no specification of format. A plain chat model would have to ask you to paste the data or would guess at numbers. An agent can go look.

Step 1 · Orient

The agent's first move is not to write anything — it looks at what is actually in the folder.

[agent lists the folder]
  sales_week1.csv
  sales_week2.csv
  sales_week3.csv
  sales_week4.csv
  returns.csv
  notes.txt

[agent opens notes.txt]
  "remember returns.csv is refunds, subtract from gross before
  reporting revenue"

This step has no chat equivalent. A chat model can only work with what you type; it has no way to notice there are five relevant files, or that a text note contains an instruction that changes how the numbers should be calculated.

Step 2 · Act

With the shape of the data established, the agent writes and runs code rather than describing what code would do:

[agent runs a script]
  Loaded 4 weekly files (612 rows total)
  Loaded returns.csv (23 rows)
  Gross sales: $18,420
  Refunds: $940
  Net revenue: $17,480
  Best week: Week 3 ($5,120 net)
  Top product: iced matcha kit (204 units)

This is the same "run code" tool use introduced in Module 1 as an emergent capability of the underlying model — the difference here is that the agent decided on its own that this step was necessary and what to run, instead of a person writing the code by hand and pasting the result back in.

Step 3 · Check

Before writing the summary, the agent re-examines its own numbers — the same instinct a careful analyst would apply before sending something to an external supplier:

[agent double-checks]
  Net revenue ($17,480) does not match gross minus refunds
  as first computed ($17,500). Difference: $20.
  [re-opens returns.csv]
  One refund row was double-counted across sales_week3.csv
  and returns.csv. Corrected net revenue: $17,500.

This is the "check" part of the read/act/check/act loop from the previous page. A chat model, asked to summarize numbers you pasted in, has no independent way to catch an error like this — it can only restate what you gave it.

Step 4 · Report

Only now does the agent produce the artifact that was actually asked for:

SALES SUMMARY — MONTH OF MARCH

Net revenue: $17,500 (gross $18,420, less $920 in refunds
after correcting a double-counted entry)
Strongest week: Week 3, driven by the iced matcha kit
(204 units sold, the top seller for the month)
Trend: revenue grew each week except a dip in Week 2 that
coincided with a stockout noted in notes.txt

One flag before you send this: refunds were 5% of gross,
which is on the high side for a single month. Worth
mentioning to the supplier only if you want to discuss
product quality, not to lead with it.

Notice that the agent did something a purely obedient assistant would not: it added a flag the student did not ask for, because the instruction "I want them to see the month went well" conflicted slightly with what the data actually showed. Good agent output surfaces that tension instead of hiding it.

What just happened, in one sentence

The agent turned a vague instruction into a finished artifact by repeating a loop — orient, act, check — that a person doing the same task by hand would also follow, except the agent did it in minutes and showed its work at each stage.

Try it yourself

You do not need Claude Code installed yet to practice this. Open any chat-based LLM and paste in the raw contents of two or three small files (or a short table) along with a request as vague as the one above. Read the reply and ask yourself: which of the four steps above — orient, act, check, report — could the model actually do with only pasted text, and which steps would have required it to open the files itself?

Check your work: a chat model can only do the report step convincingly. Orient and check both require independently opening files, which plain chat cannot do — this is exactly the gap Module 3 closes once you install an agent that can act on your actual folders.
