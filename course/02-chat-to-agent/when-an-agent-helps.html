When an agent helps and when it doesn't

An agent is not automatically the better tool. It adds setup, running time, and a wider range of things that can go wrong. This page gives you a rubric for deciding, before you open one, whether a task actually calls for it.

Why this decision matters

Once you know an agent can read files and run code, the temptation is to reach for one on every task. That habit costs time: an agent that opens five files and runs three scripts to answer a question you could have answered yourself in ten seconds is not efficient, it is overhead. The reverse mistake — trying to force a task that needs real files and verification into a plain chat message — produces guesses dressed up as answers. The rubric below sorts tasks into one bucket or the other along three dimensions.

Three questions to ask

1. Task shape: well-defined, or a judgment call?

An agent is good at tasks with a checkable end state — a file produced, a number computed, a formula fixed. It is a poor fit for tasks that are really a negotiation about taste, tone, or strategy, where the "right answer" depends on a conversation, not a computation. Deciding on a marketing slogan benefits from back-and- forth chat; cleaning and totaling a CSV does not.

2. Data location: in a file, or in your head?

An agent's advantage disappears the moment the information it needs is not written down anywhere it can reach — a hallway conversation, an opinion, a fact only you know. If you would have to type the entire relevant context into the prompt anyway, opening an agent adds setup time without adding capability. The advantage shows up when the information already exists in files, spreadsheets, or systems the agent can open directly.

3. Repeatability: one-off, or something you'll do again?

A task you will only ever do once may not be worth the setup time of pointing an agent at the right folder and checking its output carefully. A task you will repeat weekly — the same report, the same cleanup, the same format — is worth the investment, because the time spent verifying the approach once pays off every time after.

Putting it together

Task Well-defined? Data in a file? Better fit
Brainstorm three taglines for a new product No No Chat
Reconcile a month of expense receipts against a budget spreadsheet Yes Yes Agent
Decide how to frame a layoff announcement No No Chat
Find every broken link across forty pages of a website Yes Yes Agent
Get a second opinion on a single paragraph you wrote Yes No — the paragraph is easy to paste in Chat

Watch for

An agent working through a loop of read/act/check can look thorough while still being wrong — it can misread a file, run the wrong calculation, or "check" its own mistake and confirm it. Speed and confidence are not the same as correctness. Module 5 covers how to verify agent output before you trust it.

Exercise: Pick the tool

For each situation, decide whether plain chat or an agent is the better fit, and name which of the three questions above made the difference.

Situation Chat or agent, and why?
You need this week's numbers pulled from six different regional CSVs and combined into one table, every Friday.
You want feedback on whether a cold-outreach email sounds too pushy.
You need to find which of two hundred product images in a folder are missing alt text.

Check your work: the first is an agent task on both data location (six files) and repeatability (weekly). The second is a chat task — it is a judgment call and the email text is easy to paste in. The third is an agent task on data location and task shape — checking two hundred files by hand is exactly the well-defined, checkable work an agent loop is built for.
