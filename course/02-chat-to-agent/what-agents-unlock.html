What agents unlock

Agents change how humans work with computers. Instead of translating every step of a business task into code or software commands, we can increasingly describe what we want to accomplish in natural language and let an agent carry out much of the technical work.

From giving computers instructions to giving them objectives

For most of the history of computing, humans have had to tell computers how to perform a task. A person first decides on the procedure and then translates that procedure into instructions the computer can execute: formulas in a spreadsheet, commands in a software package, or code written in a programming language such as Python or R.

Agents change this relationship. Because an agent can reason about a goal, use tools, observe the results, and decide what to do next, the human can increasingly focus on describing what should be accomplished rather than specifying every technical step required to accomplish it.

Example: Forecasting product sales

Imagine that an intern is asked to analyze historical sales for a retailer's products and produce forecasts for the next several months.

The traditional workflow

Traditionally, the intern would have to perform the technical workflow themselves. They might begin by opening the data and figuring out what each row and column represents. They would then identify missing values or data errors, clean and transform the data, choose an appropriate forecasting method, calculate forecasts, evaluate the results, and create figures to communicate what they found.

To make the computer perform these steps, the intern would also need to know how to express them in a form the computer understands. They might write Python or R code, construct formulas and charts in Excel, or learn the commands of a specialized forecasting package. In other words, the intern not only needs to understand the business problem; they also need to translate the solution into detailed technical instructions.

The agentic workflow

With an AI agent, the intern can begin at a higher level. For example, they might provide the sales data and say:

Goal: Analyze historical sales by product, identify important patterns, forecast sales for the next six months, evaluate the forecasts, and create clear figures that I can use in a presentation.

The agent can then carry out many of the intermediate steps itself. It can inspect the dataset, write and run code to clean the data, select and apply forecasting methods, examine the output, revise an analysis when necessary, and generate figures. Rather than manually programming each operation, the intern supervises a computer that can determine and execute many of the steps needed to reach the objective.

Traditional approach Agentic approach
Human inspects the dataset Agent can explore the dataset
Human writes formulas or code to clean data Agent can write and run data-cleaning code
Human implements forecasting methods Agent can implement and compare forecasting methods
Human runs each analysis and interprets errors Agent can run analyses, inspect results, and iterate
Human writes code or uses software to make figures Agent can generate figures from the analysis

The human role shifts rather than disappears

The important change is not that the human no longer matters. It is that the human's role moves up a level. Instead of spending most of their effort translating each step into computer code, the human can focus more attention on defining the objective, specifying what a good result looks like, providing relevant business context, identifying important constraints, and checking whether the final output makes sense.

In the forecasting example, the intern still needs to make consequential decisions. What time horizon matters to the business? Should the forecast optimize average accuracy or avoid large errors on high-revenue products? Were promotions or stockouts responsible for unusual historical sales? Which assumptions should be preserved in the forecast? An agent can perform much of the technical work, but these questions require business context, judgment, and oversight.

The shift:
Traditional computing: Human specifies the procedure → computer executes it.
Agentic computing: Human specifies the objective and requirements → agent helps determine and execute the procedure.

From programming languages to natural language

This shift also changes how humans communicate with computers. Traditional software requires instructions written in languages designed for computers: Python, R, SQL, spreadsheet formulas, menu commands, and other formal interfaces. With AI agents, natural language itself becomes an increasingly powerful way to specify work. A person can describe requirements, provide examples, react to results, and request changes using ordinary language while the agent translates those directions into the code and tool calls required to carry them out.

This does not make technical knowledge irrelevant. Rather, it changes where expertise is applied. Knowing exactly how to write a forecasting function may become less important for many users, while knowing which forecast is appropriate, what data should be trusted, what assumptions are reasonable, and how to evaluate the result becomes more important.

“Vibe coding”

In February 2025, AI researcher Andrej Karpathy gave a memorable name to one version of this new way of working: vibe coding. He opened the post that coined the term like this:

Instead of personally writing and debugging every line, he described telling the AI what he wanted, running what it produced, showing it errors, and continuing the conversation until the software worked.

The phrase captured a larger change in human–computer interaction: increasingly, you can describe an intent in natural language and allow AI to translate that intent into executable code. The human interacts with the behavior of the system while the agent handles much of the underlying implementation.

Karpathy's original description was deliberately extreme: he joked about accepting AI-generated code without closely reading it. That may be acceptable for a throwaway experiment, but it is not a good model for consequential business applications. Throughout this course, we will use the broader idea—building by describing objectives and iterating with AI—while emphasizing verification, clear requirements, and human accountability.

The broader opportunity

This shift matters well beyond software engineering. Many business tasks combine judgment with technical execution: analyzing data, building dashboards, preparing reports, researching markets, reconciling documents, monitoring operations, or creating internal tools. Agents can lower the technical barrier to performing this work by taking on more of the execution layer.

The opportunity is therefore not simply to do the same programming faster. It is to allow more people to build and automate business solutions without first becoming expert programmers. The central skill shifts from telling a computer exactly what to do at every step toward clearly defining the problem, supplying the right context, designing an effective workflow, and evaluating whether the result is good enough to use.

Exercise: What would you delegate?

Think of a repetitive analytical or operational task from a class, internship, student organization, or job. Write down:

  1. the business objective you are trying to achieve;
  2. the information and tools an agent would need access to;
  3. which steps you would allow the agent to determine on its own; and
  4. which decisions or outputs should still require human review.

The goal is not to design the technical implementation yet. Instead, begin practicing the shift from thinking about commands to thinking about objectives, context, constraints, and evaluation.
