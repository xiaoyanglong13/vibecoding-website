The agent mental model

A chatbot answers what you type into it. An agent can look at your files, run commands, and keep working through several steps toward a goal before reporting back. This page builds the vocabulary you will use for the rest of the course.

What changes when the AI can act

Remember that early large language models were primarily used as text generators: a user provided a prompt, and the model produced a response. As models became more capable, researchers found that they could often solve complex problems more effectively by breaking them into intermediate reasoning steps. But reasoning alone had an important limitation: the model could only work with the information available in its prompt and internal knowledge.

A major next step was to give LLMs access to tools, such as search engines, calculators, databases, and software functions. This allowed models not only to reason about a task, but also to take actions and obtain new information. In 2022, researches at Princeton University and Google introduced the influential ReAct approach—short for reasoning and acting. ReAct formalized a simple but powerful pattern: reason → act → observe → reason again. Rather than producing an answer immediately, the model can decide on an action, inspect the result, and use that new information to determine what to do next.

This iterative loop provides much of the conceptual foundation for modern AI agents. Instead of requiring a human to specify every individual step, an agent can be given a broader goal and determine a sequence of actions needed to pursue it. Modern agents extend this basic idea with features such as planning, memory, multiple tools, permissions, and guardrails. A useful way to think about the progression is: LLM → reasoning → tool use → reason–act–observe loops → agents. The key shift is from AI that primarily responds to instructions to AI that can increasingly decide and execute the next steps toward a goal.

A useful analogy: the junior analyst with desktop access

Think of plain chat as an analyst you can only talk to through a closed door. You describe the task out loud, they think for a moment, and they shout an answer back — they cannot open your files, run a calculation, or double-check a number against the source data. An agent is the same analyst let into the room, with your laptop in front of them. They can open the spreadsheet, write and run a script, notice that a column does not add up, fix it, and only then come back to you with a finished summary. The judgment is the same; the ability to act on it is new.

Capability Plain chat Agent
Reads your files No — only what you paste into the message Yes — can open, search, and read files directly
Runs code or commands No — can only describe what code would do Yes — executes code and reads the actual output
Works in multiple steps No — one message in, one message out Yes — repeats read/act/check until the task is done
Checks its own work No — cannot verify a claim against real data Yes — can re-open a file or re-run code to confirm a result

The same request, two ways

Suppose you have a messy sales CSV and ask for a one-paragraph summary of this quarter's performance.

In chat, you would have to paste the numbers yourself, and the model would summarize whatever you pasted — with no way to check it against the full file:

You: Here are our Q2 numbers: [pasted table]. Summarize in one paragraph.
Model: Q2 revenue was $412K, up 9% from Q1, driven mainly by the
Northeast region...

As an agent, you can simply point at the file. It opens it, computes the totals itself, and can catch problems you did not paste in — like a duplicate row inflating the total:

You: Summarize this quarter's sales performance from sales_q2.csv.
Agent: [opens sales_q2.csv]
       [notices row 214 is a duplicate of row 213, excludes it]
       [computes region totals and quarter-over-quarter change]
       Q2 revenue was $398K, up 6% from Q1 after removing one
       duplicate entry (row 214). Growth was concentrated in the
       Northeast region (+18%)...

Exercise: Chat or agent?

For each task below, decide whether it describes a plain chat interaction or an agent interaction.

Task Chat or agent?
You paste three paragraphs and ask for a shorter version.
You ask it to open every invoice PDF in a folder and total the amounts.
You ask it to explain what a P/E ratio means.
You ask it to find and fix a broken formula in a spreadsheet, then confirm the fix by recalculating.

Check your work: rows 1 and 3 need nothing beyond the text in the message, so plain chat is enough. Rows 2 and 4 require opening files and verifying a result against them — that requires an agent.
