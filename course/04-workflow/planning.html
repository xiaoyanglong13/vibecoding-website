Plan before you execute

The single highest-leverage habit in this course: before a complicated task, ask the agent to plan first, read the plan, and only then let it build. This page covers why that order matters and how to switch into plan mode wherever you work.

Why plan first

An agent that starts writing code, or drafting a document, or restructuring a spreadsheet before it has told you its approach is easy to trust in the moment and expensive to fix later. A wrong assumption made in the first thirty seconds of execution can produce an hour of output built on that assumption. Reading a plan takes two minutes. Reading a plan is also much easier than reading a diff, a finished draft, or five hundred lines of code — a plan is written in plain language, at the level of a project outline, so you can catch a wrong assumption before it becomes a wrong deliverable.

“1-shot” means getting a correct result on the first try, without a round of fixes afterward. That is the payoff: the time you spend reviewing a plan is time you get back, many times over, by not having to unwind a wrong build.

How to toggle between modes

Most agent tools now separate planning from execution as two distinct modes, and let you switch between them mid-conversation. In plan mode, the agent can read files and think, but it cannot edit, run code, or otherwise change anything — it can only propose. Once you approve the plan, you switch to execute mode and it carries the plan out.

Tool How to enter plan mode
Claude Code Press Shift+Tab twice to cycle to plan mode, or type /plan
OpenCode Press Tab to switch between Build and Plan modes
Codex CLI Type /plan followed by a description, or press Shift+Tab to cycle modes
Tip The exact keybinding changes as these tools update — if the table above stops matching what you see, check /help (or the equivalent) inside the tool itself. What stays constant across all three is the underlying idea: a read-only mode for thinking, and a separate mode for doing.

A good rhythm: start every non-trivial task in plan mode. Read the plan the way you'd read a one-page memo before a meeting — does the approach make sense, is anything missing, did it misread your intent anywhere? Push back if something's off; the agent will revise the plan, not the (nonexistent) work. Only once the plan looks right do you switch to execute mode and let it run.

Exercise: Plan first, on purpose

Pick a task you'd normally just ask an agent to do directly — cleaning a small dataset, drafting an email, writing a short script. This time, open in plan mode and ask for a plan before any work starts. Read the plan and answer:

  • Did it correctly understand what you actually wanted?
  • Is there a step you would have had to correct after the fact, if it had just gone ahead?
  • Is anything in the plan more (or less) work than the task needed?

Then switch to execute mode and let it build. Compare how this felt to a task you've run without planning first.
