Setting up your information environment

An agent is only as good as what it can see. Before you ask for anything, spend a few minutes making sure the right files exist, are named clearly, and are explained — so the agent starts every session already oriented.

Recall the workflow

Module 1 introduced the loop behind most useful AI work:

1. Give context.
2. Specify the task.
3. Inspect the output.
4. Revise the request.
5. Verify the result.
Where this page fits This page is entirely about step 1 — give context — for projects where the context isn't a paragraph you can type, but a folder of files. The better that folder is organized, the less of your prompt has to do the work.

Start with the project folder

The first step to setting up your information environment is setting up your project folder. Put every file the task depends on inside it — and only those files. If the folder is doing more than one job, split it into subfolders with names a stranger could guess the contents of without opening them:

monthly-close/
├── inputs/          (this month's raw exports)
├── references/       (last month's approved output, style examples)
└── outputs/          (what the agent produces)

inputs, references, and outputs is a pattern worth reusing across projects: it separates what changes each time you run the task from what stays fixed, and from what the agent hands back to you.

Tell Claude what each file is

Once the folder exists, the agent still doesn't know what's in it or why. You have two ways to close that gap.

Example 1: Tell it directly

If you already know what each file is, say so up front. This is faster and leaves less room for the agent to guess wrong:

Prompt
This folder has three subfolders. inputs/ has this month's raw
data exports — treat these as read-only. references/ has
last month's approved output, which is the format to match.
outputs/ is empty; that's where finished work should go.

Read through inputs/ and references/ and summarize what you see
before we start.

Example 2: Ask it to explore

If you inherited the folder, or aren't sure what's in it yourself, ask the agent to look and report back instead of guessing at the structure yourself:

Prompt
Explore this folder and its subfolders. For each file, tell me
what it appears to contain and how it might relate to the other
files. Flag anything that looks like it might be sensitive or
that you're not sure how to interpret.

Either way, do this before you ask for the real task. A short summary you can correct — “actually, ignore the 2024 files, we only care about this year” — is much cheaper than an agent that misreads the folder and builds on top of that misreading.

When the folder gets complicated

As your projects get more complicated, they can involve many folders and subfolders with many different pieces that aren't always relevant to the current task. If you ask the agent to parse all of that by itself every time, it has to read every file and re-derive the context from scratch in every new session — which burns tokens and time unnecessarily, and it's easy for it to miss something buried three folders deep.

The fix is a short guideline document — often just CLAUDE.md or a README sitting at the top of the folder — that records the structure of the project: what each subfolder is for, where to find the file that matters for a given kind of task, and anything that's read-only. The agent reads that one short document first, and goes straight to the relevant files instead of exploring the whole tree cold.

# Project guide

## Folders
- inputs/       This month's raw exports. Read-only.
- references/   Prior approved outputs. The format to match.
- outputs/      Finished work goes here.

## Where to look
- For formatting questions, see references/.
- For this month's numbers, see inputs/.
- Never edit files in inputs/ or references/ directly.
Tip Not every task needs a standing guideline document. For a one-off file that's only relevant to the current conversation, it's often faster to just drag and drop it into the chat instead of explaining where it lives. Save the guideline document for folders you'll come back to more than once.
