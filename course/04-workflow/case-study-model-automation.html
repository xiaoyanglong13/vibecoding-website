Case study: model automation

A recurring, higher-stakes task where planning, an information environment, task specification, and memory stop being nice-to-haves and start being the reason the workflow can be trusted every month. The full build is already written up in the use case library — this page just points you to it.

Where each skill shows up

As you read the case, watch for these four moments — each one is the case's version of a page you just read:

  • Plan before you execute. The session opens with a plan request — role, files, steps, constraints — and the plan is read back before any code runs.
  • Information environment. Three files in one folder; the account-mapping file is the real-world messiness that makes the case worth doing.
  • Specifying the task. Filling in known accounts is a builder step and runs unattended; deciding what an unmapped account maps to is a thinker step — and gets a human checkpoint pinned over it.
  • Memory across sessions. A closing prompt turns the whole session into workflow.md, so next month is one line instead of six prompts.
