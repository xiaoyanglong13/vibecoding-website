Extend your agent: Skills and MCP

You have learned to give an AI agent instructions and organize the information it needs. Two more tools can make it useful across larger projects: skills help it follow reusable procedures, while MCP connects it to external tools and data.

Two problems you may encounter

Imagine you use an agent to prepare a sales report every Monday. You repeatedly explain what metrics to calculate, what to flag, and how to format the report. Even when the instructions are similar, the results sometimes look different.

Now imagine the sales data lives in an online system rather than in your project folder. You have to download the latest data and upload it to the agent every time.

These are two different problems, with two different solutions:

  • Skills: Give the agent a reusable procedure for how to perform a task.
  • MCP: Give the agent access to external tools and information it needs for the task.

Skills: Reuse a way of working

A skill is a saved set of instructions for a particular kind of task. It can also include templates, reference files, or scripts. Think of it as a standard operating procedure (SOP) for your AI agent.

For example, a weekly-sales-report skill might tell the agent to inspect a dataset, calculate key metrics, identify important changes, flag questionable data, and produce a concise management report. The next week, you can reuse the procedure instead of explaining every step again.

Example 1: A weekly sales report skill

In Claude Code, a project-level skill can be stored like this:

.claude/
└── skills/
    └── weekly-sales-report/
        └── SKILL.md

The SKILL.md file might contain:

---
name: weekly-sales-report
description: Analyze sales data and prepare a concise weekly management report.
---

When preparing a weekly sales report:
1. Inspect the data and explain any missing fields.
2. Calculate total sales and relevant changes over time.
3. Identify the three most important business insights.
4. Flag missing values, anomalies, and uncertain conclusions.
5. Produce a concise, clearly labeled management report.

Do not invent missing numbers. Explain important assumptions.

You do not need to memorize the file format. You can ask Claude Code to create and revise the skill for you. Once available, you can invoke it with /weekly-sales-report; depending on its configuration, Claude may also select it when the task is relevant.

Example 2: Ask the agent to create the skill

Prompt
Help me create a reusable Claude Code skill called
weekly-sales-report.

Whenever I use it, the agent should:
1. Inspect the sales data and check for missing values.
2. Calculate key sales metrics and changes over time.
3. Identify three meaningful business insights.
4. Flag questionable calculations or assumptions.
5. Produce a concise management report.

First show me the proposed workflow. Then create the
skill and explain how to invoke and test it.

Test the skill on a sample dataset. Check both the calculations and the quality of the recommendations. If something is wrong or unclear, revise the skill and test it again.

Remember A skill makes a procedure easier to reuse; it does not guarantee accurate results. Apply the verification habits from Module 4 each time you use it.

MCP: Connect the agent to other tools

Your agent can already work with files in its project folder. But useful information often lives elsewhere: Google Drive, GitHub, Slack, Notion, or a company database.

MCP stands for Model Context Protocol. It is an open standard for connecting AI applications to external tools and data sources. An MCP server makes specific capabilities available to the agent, such as searching documents, retrieving records, or creating an issue in a project tracker.

Think of an MCP connection as providing access to a workplace system:

AI agent
   |
   |  MCP connection
   v
External service (e.g., GitHub or Google Drive)
   |
   v
Available actions: search, read, or update
(depending on the connection and permissions)

The agent does not automatically gain access to everything. The available actions depend on the MCP server, your account, and the permissions you grant.

Example 3: Preparing for a project meeting

Suppose your team stores project documents in Google Drive and tracks work in GitHub. Without connections, you might download the documents, copy open issue descriptions, and paste everything into a chat.

With suitable connections, the agent can retrieve relevant information from those services directly.

Prompt
Review the latest project plan in Google Drive and
open issues in our GitHub repository.

Summarize the three most important unresolved problems
for tomorrow's team meeting. For each problem, give
the evidence and a link to its source.

Do not modify any documents or GitHub issues.

Other examples include retrieving customer feedback from a connected database, searching team discussions, or creating tasks in a project management tool. Whether a particular action is possible depends on the connection you have configured.

Try an MCP connection

In Claude Code, you can inspect configured MCP connections using /mcp. Setting up a new connection may involve choosing a trusted provider, authenticating with your account, and granting permissions.

You can ask your agent to help with the setup, rather than figuring out each technical step on your own.

Prompt
I want to connect Claude Code to GitHub through MCP.

Help me:
1. Find an official or trusted connection option.
2. Explain which actions and information it can access.
3. Walk me through setup and authentication.
4. Test it using a read-only task.

Show me the configuration and permissions first.
Do not install anything, change permissions, or modify
GitHub content without my approval.
Use care with connections Connect only trusted services. Review whether a connection can merely read information or also create, change, or delete it. Be careful with private data, and verify retrieved information before relying on it. External content can also contain misleading or malicious instructions.

What should you use?

You have now seen three ways to help an agent work more effectively. They solve different problems.

ToolMain questionExample
Project instructions (Module 4)What should the agent know?Never modify raw data files.
SkillHow should it do this recurring task?Prepare a weekly sales report using our format.
MCPWhat external information or tools can it access?Read the latest sales file from Google Drive.

These tools complement one another. For a weekly sales report, an MCP connection might retrieve the latest data, a skill might specify the analysis and report format, and project instructions might supply company-specific rules.

Note that a connection alone does not schedule the report to run every Monday. Scheduling requires a separate automation mechanism.

Exercise

Required: Create your own skill. Choose a task you might perform more than once, such as summarizing meeting notes, cleaning survey data, evaluating suppliers, or creating a management report.

  1. Describe the task, desired output, and any important rules to your agent.
  2. Ask it to create a reusable skill. Review the proposed instructions before saving.
  3. Invoke the skill on a sample task and inspect the result.
  4. Identify one weakness. Revise the skill and test it again.

Optional extension: Explore an MCP connection to a service you already use. Ask the agent what it would be allowed to do, review the permissions, and (if appropriate) test a read-only request.

Reflect: How is your new skill different from saving a prompt? What can MCP enable that a skill alone cannot? Which parts of the work still require your judgment?

Takeaway Skills provide a repeatable method. MCP provides access to external systems. Both expand what an agent can do, but neither replaces careful oversight and verification.
