Useful skills for working with AI

You don't have to create every skill yourself. Others have developed reusable skills that can help AI agents explore ideas, plan work, investigate problems, and test results. Let's look closely at one skill that can make an agent a more thoughtful collaborator: Brainstorming.

Why use someone else's skill?

In the previous optional lesson, you learned that a skill packages instructions into a reusable workflow. You can write your own, but you can also install skills created by other people. A directory such as Skills.sh can help you discover them.

Remember that a skill is not a new AI model. It gives your agent a particular procedure to follow. You could often achieve something similar with a carefully written prompt; the advantage is that the procedure is packaged for repeated use.

Featured skill: Brainstorming

The Brainstorming skill from the Superpowers collection is designed to help an agent understand what you actually want before it begins building. It emphasizes clarifying the goal, considering approaches and trade-offs, describing a proposed design, and obtaining your approval before implementation.

This is different from asking the agent to produce a long list of creative ideas. Brainstorming is a structured design conversation that helps turn an initial request into a well-defined plan.

Recall the workflow from Module 4:

Explore → Plan → Execute → Verify

Brainstorming is particularly useful in the Explore stage and when moving into Plan. It encourages you to resolve important questions before the agent starts implementing a solution.

Example: Revisit the coffee shop dashboard

Recall the coffee shop dashboard from Module 4. Suppose you start with this request:

Initial request
Build a dashboard for a coffee shop owner.

Without further discussion, an agent might pick a set of common charts and start building. The dashboard could look polished without helping the owner make meaningful decisions.

With Brainstorming: Understand the problem first

The agent could ask questions like these (illustrative examples, not a fixed script):

  • What decisions should the owner be able to make using this dashboard?
  • Is the priority understanding sales, improving profitability, or planning staffing?
  • What data is available, and what important information is missing?

Based on the answers, the agent can compare possible designs and their trade-offs. For example, a sales-focused dashboard may emphasize revenue, order frequency, and average order size; a profitability-focused dashboard would need cost or margin information as well.

The agent then proposes a design for you to review. You can revise it before implementation begins. The goal isn't to ask more questions for their own sake; it's to avoid building the wrong thing.

Install and try Brainstorming

If you're using Claude Code, first review the skill's instructions. One installation method listed on Skills.sh is:

npx skills add https://github.com/obra/superpowers --skill brainstorming

Run the command in a terminal only after reviewing the source and installation prompts. The installer may ask you to select an agent or installation scope. Follow the current instructions rather than assuming every setup looks the same.

Once installed, ask Claude Code to use the brainstorming skill explicitly for this exercise. You can also check which skills Claude Code recognizes. Skills may be selected automatically when their descriptions match the task, but automatic invocation is not guaranteed; explicit invocation is more predictable while you're learning.

Exercise: Redesign the coffee shop dashboard

Prompt
Use the brainstorming skill to help me design a
coffee shop dashboard.

The dashboard should help the owner make better
business decisions. I haven't decided which
metrics or charts it needs.

Work with me to clarify the goals, explore
possible approaches, and propose a design.
Do not start building the dashboard yet.
  1. Install and review the Brainstorming skill (or have your instructor demonstrate it).
  2. Use the prompt above. Answer the agent's questions as if you were designing the dashboard for a real coffee shop owner.
  3. Ask the agent to compare possible dashboard designs and explain the trade-offs.
  4. Stop when you have a proposed design. You do not need to implement it.
  5. Compare your design with the dashboard example from Module 4. What would you change, and why?

Reflect: What did the skill help you notice that you might otherwise have missed? Could you have achieved the same result by asking an ordinary chatbot to clarify requirements before building?

Tip Use structured brainstorming selectively. It can be valuable for open-ended projects, but unnecessary for a small, well-specified change. If you already know exactly what you want, a long design discussion may just add friction.

Other skills worth exploring

Brainstorming is only one example. These other published skills can help at different points in your workflow:

SkillWhat it helps withExample from this course
Grill Me Challenge assumptions and uncover missing requirements Question a financial-model automation plan before implementing it
Web App Testing Use browser automation to check how a web app behaves Test dashboard filters, buttons, and charts
Systematic Debugging Investigate the cause of a failure before attempting fixes Diagnose why a dashboard or deployment stopped working
Verification Before Completion Require evidence before claiming work is finished Check whether an agent actually ran relevant tests
Writing Plans Turn an approved design into implementation steps Plan a more complex application or automation project

Not every skill is appropriate for every project. In particular, Web App Testing is built for browser-based applications; it does not replace spreadsheet reconciliation or a careful review of a written report.

Before you install Skills from public repositories are third-party instructions. Some also include scripts or other executable resources. Review what a skill does, where it comes from, and what permissions it needs. Installing more skills also adds some discovery overhead, and invoking long skills uses additional context and tokens. Start with a few that address genuine needs.

Takeaway

A useful skill can make an AI agent a more disciplined collaborator, not just a faster producer of output. Brainstorming helps you think through what to build and why before asking the agent to build it. Other skills can help you challenge plans, diagnose failures, and test results. The important skill on your part is knowing when each procedure is worth using.
