Why move beyond the browser?

A browser is a great place to talk with AI. But to let an agent work on a real project, it often needs a workspace where it can inspect files, use tools, create outputs, and test its work.

An agent needs a workspace

For the kinds of projects we will build in this course, an agent may need to:

  • inspect a folder and understand how its files fit together,
  • read several documents, spreadsheets, or data files,
  • create and edit files directly in the project,
  • run tools or commands to perform work,
  • check whether its output actually works, and
  • keep project instructions and memory alongside the work.

That usually means giving the agent controlled access to a local workspace. This does not mean giving it unrestricted access to your entire computer. You choose the project, tools, and permissions it can use.

A browser gives you a conversation. A local agent gives the AI a place to work.

Two common ways to work locally

There are two common ways to put an AI agent closer to your files and tools: use a graphical app, or use a terminal-based agent.

Graphical interface

Desktop or IDE-style app

You work through buttons, menus, file pickers, previews, and permission dialogs. This usually feels more familiar when you are getting started.

Terminal interface

Agent in the terminal

You start the agent inside a project folder and interact through text. More of what the agent is doing is visible directly in the workspace.

Similar agent capabilities, different interfaces

Major AI ecosystems now offer several ways to work with agents. The exact products will continue to change, but the basic pattern is useful:

Ecosystem Graphical experience Terminal / local agent
Anthropic Claude desktop app Claude Code
OpenAI ChatGPT and Codex app experiences Codex CLI
Google Antigravity graphical experiences Antigravity CLI
OpenCode — OpenCode

Some ecosystems also offer an IDE integration, which sits between the two: you get a graphical editor and file browser, while the agent can still work directly with the local project.

The important point is not the product name. Similar agent capabilities can be wrapped in different interfaces, and those interfaces expose different amounts of the underlying work environment.

Why learn the terminal?

Graphical apps are often easier to start with. They give you familiar buttons, menus, previews, and permission prompts. But terminal-based agents offer several important advantages once you know how to use them.

Advantage What it means in practice
More portability Once you are comfortable in the terminal, the skill transfers across tools such as Claude Code, Codex CLI, OpenCode, and other model providers. You are less tied to one company's interface or subscription.
More transparency You can often see details that graphical apps hide or summarize, such as token usage, commands being run, and other low-level activity.
More flexibility Terminal tools usually expose more settings. Depending on the tool, you may be able to switch models, change providers, add tools, or change how the agent works without rebuilding your workflow.
A clearer work environment You can more easily inspect exactly which folder the agent is working in, what files it can access, what tools are available, and which instruction, memory, and configuration files are active. Graphical apps often deliberately hide or abstract more of this setup behind the interface—for example, permissions, connected folders, default tools, background state, or where execution is happening—making the system easier to use but less transparent.

Graphical apps often do more work behind the scenes. They may provide default tools, maintain extra state, or load instructions in ways that are convenient but less visible. In the terminal, more of that setup is exposed, which makes it easier to understand and control the agent's environment.

The terminal is a transferable skill. App interfaces change, pricing changes, and new models appear. A terminal-based workflow is easier to carry across tools.

This does not mean terminal tools are always better. Graphical apps can be faster and more comfortable for many tasks. The reason we teach the terminal is that it gives you more visibility into how the agent works and a skill that transfers across systems.

Setup for this course

In this course, we will primarily use Claude Code through the terminal inside VS Code. This may look less familiar than a browser or desktop app at first, but it makes the agent's workspace easier to understand.

If, for technical reasons, you cannot get this setup to work, you may use the Claude app instead. The main ideas and workflows in this course will still apply, with the caveats described in the table above.
